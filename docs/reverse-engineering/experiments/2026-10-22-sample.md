# SAMPLE — which rows Desktop picks

**Question.** `SAMPLE(n, table, order [, direction]...)` returns n rows "evenly
spaced" over the ordered table. Which rows exactly, which direction is the
default, how are `1` and `0` read, and do order columns after the first count?

**Method.** Black-box: 53 `EVALUATE SAMPLE(...)` queries sent to Power BI
Desktop 2.157's local Analysis Services instance with a throwaway synthetic
model open (Windows, 2026-10-22). Every table came from `GENERATESERIES`, so no
model's data is involved: `SELECTCOLUMNS(GENERATESERIES(1, N), "v", [Value])`
for N = 10, 11, 20, 30, 100, 101, 912 and 1000, a squares column (`[Value] *
[Value]`) to tell spacing by position from spacing by value, and a tie column
(`INT(([Value] - 1) / 4) + 1`, four rows per value) for the order columns. The
answers are the expected values in `tests/test_sample_desktop.py`.

**Observations.**

- **Spacing is by position in the ordered table**, not by value (the squares
  1..900, n = 4: 1, 121, 400, 900). The picks are index
  `floor(i * (N - 1) / (n - 1) + 1/2)` for i = 0 .. n - 1, halves rounding
  up: all 43 spacing cases fit it (3 of 10: 1, 6, 10; 5 of 10: 1, 3, 6, 8, 10).
  Round-half-to-even differs on 6 of them.
- **n >= N** returns every row (3502 of 912), **n = 1** the first row in the
  order, **n = 0** no rows.
- **Direction:** with none given the order descends; `DESC` and `0` descend,
  `ASC` and `1` ascend (5 of 1..20: ascending 1, 6, 11, 15, 20; descending
  20, 15, 10, 6, 1).
- **Every order column counts:** `[a], ASC, [v], DESC` over the tie column
  picked v = 4, 7, 10, 14, 17 (the last of each group of four first). With
  only `[a], ASC`, rows tied under it came back in an order no column gives
  (v = 2, 6, 10, 15, 20), so the order among remaining ties is unspecified.

**Also seen.** Desktop's own visual queries pass the direction as `1`:
Performance Analyzer's export of a line chart over a date axis (a synthetic
model) shows `SAMPLE(3502, __DS0Core, 'Calendar'[Date], 1)`.

**Conclusions.** pbix-mcp orders by every order expression with its own
direction, takes the positions above in integer arithmetic, and returns no
rows for n = 0 (and for negative n, which wasn't measured). `1` ascends and
`0` descends as measured; `TRUE` and `FALSE` are read as `1` and `0`, as TOPN
reads them, unmeasured for SAMPLE. The sort is stable, so rows tied under
every order expression keep the table's order: for `[a], ASC` alone it picks
v = 1, 6, 11, 15, 20 where Desktop picked 2, 6, 10, 15, 20. Both are one row
from each value of `[a]`, which is all the test checks; Desktop's choice among
ties isn't reproduced.

**Sources.** Desktop's answers to our own queries over generated tables; our
own analysis. No Microsoft source, binaries or confidential material used.
